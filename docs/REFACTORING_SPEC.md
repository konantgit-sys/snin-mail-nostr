# SNIN Mail — Спецификация рефакторинга (v1.0, 2026-08-28)

Цель: подготовить сервис к вертикальному росту (200+ пользователей) в рамках
экосистемы SNIN: уникальный визуал в стиле SNIN Network, модульная архитектура
фронта и бэка, устойчивость к нагрузке, честный мониторинг.

---

## 0. Текущее состояние (зафиксировано 2026-08-28)

| Слой | Факт |
|---|---|
| Бэкенд | FastAPI, порт 8123, **1 процесс uvicorn**, sync-маршруты (threadpool) |
| БД | SQLite WAL, busy_timeout 5с, индексы: inbox(received), inbox(read), outbox(sent). **Нет составного (owner, received_at)** |
| Фронт | Монолит 76 КБ inline (index.html), зеркала js/*.js, дубли *2.js (удалены 2026-08-28) |
| Мост | 1 процесс на все ящики, NIP-44/59 gift wrap (CPU-bound), kind:1301, Blossom NIP-96 |
| Аккаунты | 21 (1 admin, 20 user), 36 писем inbox, 41 outbox, БД 812 КБ |
| Инфра | Контейнер: RAM 12 ГБ (занято ~96% всеми демонами), диск 20 ГБ (было 98% → 80% после чистки) |

Главные риски на 200 пользователей:
1. **RAM контейнера 96%** — почта не влезет физически, нужен вынос/чистка демонов.
2. **1 воркер + sync-маршруты** — лаги при одновременных запросах.
3. **Нет составного индекса** — деградация выборок при росте таблицы.
4. **Монолит фронта** — тормозит разработку и кэширование.

## Порядок и зависимости

Фаза 0 → 1 → 2 → 3 → 4 → 5.
0 можно делать сразу (защита). 1 и 2 — параллельно с 3 (дизайн-система
переиспользуется в модулях). 4 зависит от 0 (после workers). 5 — по решению
владельца, независимо.

Оценка: 0 (1ч) → 1 (3-4ч) → 2 (2-3ч) → 3 (4-5ч) → 4 (3-4ч) → 5 (2-4ч).
Итого ~15-21 час.
